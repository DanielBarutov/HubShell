HubShell — установка на Windows 10/11 x64

ЧТО ЗАПУСКАТЬ
HubShell.exe — клиент: окно входа и игровой сеанс.
HubShell.Watchdog.exe — фоновая служба: следит за клиентом и выполняет обновления.
Оба EXE нужны. Службу вручную двойным щелчком не запускайте.

УСТАНОВКА ИЛИ ОБНОВЛЕНИЕ
1. Завершите игровой сеанс. В PowerShell от администратора остановите службу:
   Get-Service HubShell.Watchdog -ErrorAction SilentlyContinue | Stop-Service
   После этого закройте HubShell.exe.
2. Распакуйте комплект в C:\GameClub с заменой файлов от администратора.
   Сохраните существующий server.ini и файлы данных/идентичности этого ПК.
   При первой установке скопируйте server.ini.example в server.ini
   и укажите адреса своего сервера и публичный ключ V2 snapshot.
3. В C:\GameClub запустите start-service.cmd от имени администратора.
   Он устанавливает/обновляет и запускает службу. Клиент запускается службой.
   Для ручного запуска клиента используйте HubShell.exe.

НАСТРОЙКА АВТООБНОВЛЕНИЯ (ОДИН РАЗ НА КАЖДОМ ПК)
1. Сервер должен быть обновлён до этого же CI-выпуска. Назначьте MAC этого ПК
   в админке и один раз запустите GUI под обычной игровой учётной записью,
   чтобы сервер зарегистрировал её installation_id. Закройте GUI без запуска игры.
   Запуск GUI под другой администраторской учётной записью создаёт другую установку.
2. Оператор получает индивидуальный enrollment JSON через
   POST /api/v1/client-updates/credentials/<device_id> с правом workstations.manage.
   Сохраните ответ вне Git в файл, доступный только администратору этого ПК.
   Он содержит одноразово выданный секрет службы; не передавайте его в переписке.
3. В PowerShell от администратора выполните (замените адрес и пути):
   .\start-service.ps1 -UpdaterEnrollmentFile C:\Private\pc-enrollment.json `
     -UpdateBackendAddress http://192.168.0.21:8100 `
     -UpdatePublicKeyPath C:\Private\release-public-key.pem
   Используйте доверенный ключ CI, а не ключ из произвольной загрузки.
   installation_id в JSON должен совпадать с установкой GUI игровой учётной записи.
4. После успешной настройки защищённые данные хранятся в .client-updater.json
   (DPAPI этой машины; доступ SYSTEM/Administrators). Уберите исходный JSON
   с секретом из общедоступных папок и безопасно удалите временную копию.
5. Серверная периодическая задача раздаёт пакет по локальной сети. При включении
   служба проверяет назначение; занятый ПК обновляется после окончания сеанса.
   Ошибка удерживает только этот ПК. Новый вход до проверки версии не разрешается,
   начатая игра и локальные финансовые файлы сохраняются.

Обычный start-service.cmd без параметров настраивает только восстановление клиента.
Повторная установка с сохранённым .client-updater.json проверяет его и сохраняет
настройку обновлений. GUI обновляется автоматически; сама служба обновляется
полным комплектом вручную после остановки. Не копируйте identity, ledger,
.client-updater.json или enrollment JSON между ПК.

Если установка откатилась, исправьте причину и в админке откройте
«Настройки → Обновления клиентов → Повторить с текущей версией» для этого ПК.
Повтор использует актуальный проверенный выпуск сервера, сохраняет предыдущую
ошибку и оставляет ПК закрытым до подтверждения запуска. Другие ПК продолжают
работать. Не удаляйте ledger/outbox или journal обновления ради снятия блока.

Первую установку проверьте на одном свободном ПК. Windows-пилот ещё не выполнен.
