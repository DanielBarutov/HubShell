# GameClub frontend

Операторская панель использует плотный desktop-first workspace: тёмная навигация
слева, тёмная рабочая область, карта мест, status-driven карточки и контекстная
right sliding panel. Визуальный ориентир — сценарии SmartShell, но брендинг и
ассеты не копируются. Основная дизайн-система находится в `src/index.css`, а
бизнес-правила остаются в backend. Продажа из карточки свободного ПК открывает
полноразмерное checkout-окно с выбором клиента/гостя, карточками тарифов и
товаров по категориям и локальной корзиной; актуальная открытая смена
подставляется автоматически.

Операторская web-оболочка на React, TypeScript, Tailwind CSS и Lucide.

## Транспорт

Браузер работает через HTTP JSON BFF на FastAPI (`VITE_API_URL`). Нативный gRPC
остаётся транспортом Windows-клиента и внутренних сервисных границ. `GameClubApi`
не валидирует JWT самостоятельно и не хранит access token в `localStorage`:
короткоживущий access token живёт в памяти, а ротируемый refresh token сохраняется
в `localStorage` и восстанавливает сессию после reload или перезапуска браузера.
Backend по умолчанию выдаёт refresh token на 90 дней.

## Запуск

```text
npm install
npm run dev
npm run typecheck
npm run build
```

При отдельном `npm run dev` Vite использует порт `3101` и проксирует `/api` на
FastAPI `8100`; production frontend в Compose доступен на host-порту `3100`.

По умолчанию dashboard использует live-режим и данные backend. Для локальной
визуальной отладки задайте `VITE_GAMECLUB_DATA_MODE=mock`. В live-режиме появится форма входа,
workstations будут загружаться через FastAPI BFF, состояние обновляется раз в 15
 секунд, а поиск клиентов и пополнение депозита используют typed API boundary.
Брони, активные игровые сессии, клиенты и тарифы также загружаются из backend, а reservation API поддерживает get,
update, activate, complete, no-show и cancel. Команда запуска/остановки сессии из панели ПК
отправляется через защищённый BFF. В dev Vite проксирует `/api` на
локальный FastAPI `127.0.0.1:8100`.
Live dashboard показывает только данные, доступные текущему BFF: активные сессии,
брони, сумму клиентских депозитов, read-only выручку за текущий день и последние
операции из защищённого audit read model. Если отчёт недоступен, вместо него
остаётся явный `—`, а live-режим не подменяет показатель фиктивным числом.
В live-каталоге оператор может создать категории товаров/напитков, изменить или
удалить их, создать товар, discount rule или draft-тариф,
а затем опубликовать либо архивировать тариф через BFF.
Из таблицы клиентов доступна контекстная карточка с балансом, бонусами и
категорией скидки; последние операции balance ledger загружаются в этой же
панели через защищённый BFF, а кнопка пополнения открывает flow уже с выбранным
клиентом.
Для live-ПК доступно явное отключение из контекстной панели с подтверждением;
после этого backend блокирует обычные device-команды для места.
В разделе «Настройки» оператор может сохранять группы ПК и темы
`standard`/`vip`/`neon`/`minimal`; Windows-клиент получает тему через heartbeat.
В CRM можно создать клиента с ником, телефоном и категорией скидки; баланс и
бонусы не задаются напрямую из формы. Гость в операторском сценарии не является
отдельным профилем: при создании брони или старте сессии без выбранного клиента
backend фиксирует участника как «Гость» без баланса и регистрации.
В разделе «Касса» оператор может открыть смену на register, записать приход,
расход или signed-корректировку, закрыть смену по фактическому остатку и увидеть
расхождение и историю закрытий. Кассовый раздел использует тот же typed BFF и
не смешивает наличный ledger с балансом клиента или session charge. Для
корректировки и закрытия с расхождением BFF сначала запрашивает отдельное
supervisor approval, после чего отправляет операцию с approval ID.
