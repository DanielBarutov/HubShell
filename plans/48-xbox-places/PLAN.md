# План 48 — места Xbox и гостевые продажи времени

Статус: `implemented` (первый этап, локальная проверка)  
Согласовано: 2026-10-13  
Владельцы: backend и frontend  
Зависимости: Workstations, Catalog, Sessions, Billing, Cash Shifts, Analytics.

## Цель и границы

Добавить Xbox на общую карту мест, продавать время через оператора и учитывать
финансы в существующих журналах и аналитике. Клиент на приставке не требуется.
Первый этап реализован в backend/frontend; Sonoff остаётся отдельным этапом.

## Согласованные правила первого этапа

- Место Xbox имеет название, зону и позицию на общей карте. Это отдельный тип
  оборудования без MAC, enrollment, device identity, heartbeat и local ledger.
  Серверный учёт Xbox не возвращает V1 runtime на ПК; все новые ПК остаются V2-only.
- Одна приставка оплачивается целиком независимо от числа игроков. Одна активная
  сессия на место; всегда анонимный гость, без выбора/создания клиентского профиля.
- Оплату принимает оператор существующим способом прямой гостевой оплаты.
  Депозит, бонусы, guest-баланс и поминутное списание запрещены.
- Оператор создаёт Xbox-тариф с названием, длительностью и ценой в целых копейках.
  Тип оборудования проверяется сервером: Xbox-тариф недоступен ПК, PC-тариф
  недоступен Xbox, в том числе тариф без ограничения зоны. Ограничение зоны
  не заменяет ограничение типа оборудования. Дополнительные тарифные правила
  ПК не вводятся в простую форму Xbox по умолчанию.
- Успешная продажа на свободное место сразу запускает сессию. До подтверждения
  продажи сессия не начинается. Бесплатный login grant для Xbox не применяется.
- Продажа ещё одного Xbox-тарифа на занятом месте продлевает ту же активную
  сессию на оплаченную длительность; каждая продажа имеет собственный финансовый
  факт. Новая сессия при продлении не создаётся.
- При окончании времени сессия автоматически завершается. Оператор может
  завершить её раньше с подтверждением: весь остаток сгорает, автоматического
  возврата нет. Паузы и переносы отсутствуют. Бронирование отложено.
- Backend хранит UTC-время начала и срок окончания в PostgreSQL. При остановке
  сервера время продолжает идти; после запуска просроченные сессии закрываются
  по сохранённому сроку. Открытый браузер не требуется для завершения сессии.
- Продажи входят в общую выручку и кассовый учёт по действующим правилам способа
  оплаты. Наличные и безналичные операции не смешиваются в наличном ledger.
  Аналитика предоставляет фильтры по Xbox, конкретному месту и тарифу.
- Без реле окончание сессии прекращает только учёт; TV выключает оператор.

## Проверки и критерии готовности

- Unit/Application: запуск после продажи, добавление времени без второй сессии,
  сгорание остатка, строгая изоляция тарифов, запрет депозитов/поминуток,
  отсутствие login grant, неизменяемые снимки цены и длительности.
- API: права оператора, входная валидация, повтор запроса с тем же operation ID,
  запрет обхода типа оборудования и использования Xbox в PC enrollment/transfer.
- PostgreSQL integration: конкурентные продажи на свободное место, повтор оплаты,
  гонка продления с завершением, восстановление после частичного сбоя и рестарта,
  один финансовый эффект, срок завершения без лишнего времени простоя backend.
- Finance/Analytics: общая выручка, Xbox/place/tariff фильтры, корректный способ
  оплаты и кассовая ссылка, отсутствие двойного дохода на продаже и завершении.
- Frontend: сценарии продажи/продления/завершения, ошибки и повтор после сетевого
  сбоя, typecheck и production build; browser smoke на Linux с реальным backend.
- PC regression: существующие V2 вход, гостевая продажа и tariff matching сохраняются.

## Второй этап — дополнительная опция Sonoff

После готовности Xbox добавить необязательное управление TV для каждого места:
включение при старте, выключение при завершении, включая досрочное.
Xbox остаётся доступным без настроенного реле.

Модель из обсуждения: [SONOFF MINI-D](https://www.sonoff.ru/product/sonoff-mini-dry),
Matter и сухой контакт подтверждены
[производителем](https://sonoff.tech/en-us/products/sonoff-mini-dry-wi-fi-smart-switch-mini-d).
Исследование и инструкция подготовки — [SONOFF-RESEARCH.md](SONOFF-RESEARCH.md).
Для подтверждённого DIY-реле предпочтителен прямой HTTP по LAN; для MINI-D без
подтверждённого DIY API предложен Home Assistant → Matter. Точная модель
ранее работавшего с Gizmo реле пока не установлена.
Это исследование вариантов второго этапа; выбран прямой DIY HTTP по LAN.
DIY API v1.4 относится к старым Basic R3/RFR3/Mini, а поддержку MINI-D не доказывает.
Прямой HTTP/MQTT API MINI-D не считается подтверждённым.

Важно: [SONOFF запрещает AC-нагрузки на выходе MINI-D](https://sonoff.tech/en-us/products/sonoff-mini-dry-wi-fi-smart-switch-mini-d).
Питание модуля от сети не делает его выход пригодным для коммутации питания TV 220 В.
До выбора схемы нужны модель TV и сведения о том, куплен ли уже MINI-D.

Для аппаратной приёмки второго этапа отдельно проверить:

- подключение TV и фактическое включение после подачи питания;
- локальный контроллер/протокол, pairing и хранение секретов вне Git;
- поведение при недоступном реле, сбое включения и рестарте backend;
- подтверждение состояния, повтор команд и защита новой сессии от запоздалого OFF;
- необходимость автономного отключения TV при недоступном backend.

Проверки на реальном реле и TV обязательны для подтверждения автоматизации.

## Текущее доказательство

Реализованы миграция `20261013_0075`, типы мест/тарифов, защищённые продажи,
продление одной сессии, серверное завершение, финансовые снимки и UI.
PostgreSQL обеспечивает общий commit продажи, кассового движения, сессии и аудита;
публичные репозитории участвуют в транзакции через инфраструктурный контекст.
Блокировка места совпадает с существующей блокировкой Sessions. In-memory адаптер
предназначен для разработки и не подтверждает откат денежных операций.

Проверки 2026-10-13 на Linux:

  продажи, stop/extension, неизменяемый снимок, срок после простоя, откат наличной
  продажи при ошибке записи сессии, финансовые фильтры, запреты PC и авторизация.

- `dotnet test ./win-client/tests/GameClub.Client.Tests.csproj --configuration Debug
  --no-restore`: 167 passed. Windows host x64 Debug build на Linux: 0 warnings,
  0 errors. Исполняемый код клиента и protobuf не менялись.
- Xbox + V2 PostgreSQL итоговый срез: 33 passed, 2 skipped; Xbox отдельно: 17 passed,
  1 skipped. Пропуски относятся к memory rollback и отсутствующему Kafka/Redis.
- Frontend: 37 passed — сценарии Xbox, SaleWorkspace, PcPanel, MapScreen, BookingPanels и
  sessionTooltip; production build проходит. Chrome с реальным backend проверил
  создание Xbox без MAC, простой тариф, гостевую продажу и продление; карта
  показывает серверный остаток, панель — точный UTC-срок в локальном времени.
  Досрочное завершение проверено API/PostgreSQL и frontend-тестом; Chrome показал
  правильное предупреждение, но расширение зависло на нативном confirm.
- Миграция отдельной базы `0074 → 0075` с существующим ПК (MAC/device/installation),
  четырьмя тарифами (блочный, поминутный, с окнами, архивный), активной PC-сессией
  и подтверждённой гостевой продажей: количество строк и все прежние поля
  сравнены до/после и полностью сохранены. Старые места/тарифы/продажи получили
  `equipment_type=pc`; PC-сессия получила `expires_at=null`, пустой список Xbox-оплат.
  Новое ограничение сохраняет PC `local_ledger`, Xbox использует `server_owned`.

Ограничения общей проверки: полный Ruff обнаруживает ошибки в существующем
сгенерированном protobuf; изменённые Python-файлы проходят отдельно. Frontend lint
обнаруживает прежние неиспользуемые импорты ChevronDown (AppShell) и MoreHorizontal
(MapScreen), присутствующие в HEAD. Один тест AnalyticsView падает и на исходном
DashboardScreen из HEAD. Старые PostgreSQL concurrency fixtures создают PC
`server_owned`, запрещённый уже миграцией 0073; seeded finance fixture требует
отдельных исторических данных. Эти результаты не объявляются успешными.

Промышленная база и Compose не изменялись. Перед выпуском: резервная копия,
проверка на копии фактической базы и `uv run --directory ./backend alembic upgrade head`
при остановленных backend/worker старой версии, затем запуск новой версии.
Эта проверка подтверждает совместимость с валидной схемой 0074, но не проверяет
произвольные ручные изменения промышленной базы. Исторические zone-снимки старых
продаж не выдумываются; отсутствующая zone остаётся null.

Не проверены: живой Kafka/Redis worker, промышленное обновление, нативный Windows
(окна/трей/DPAPI) и реальный Sonoff/TV. Таймер Xbox использует существующий
`meter_active_sessions` и startup recovery, браузер для завершения не требуется.

производителя сохраняются.

HTTP контракт DIY и отказов, frontend-состояния, миграция и сборка.

Проверено: 40 backend-тестов (in-memory и PostgreSQL 0076), 1 пропуск
