# Независимое обновление ПК

Статус: in_progress. Решение согласовано 2026-11-06.
Заменяет обычное общее обновление парка из PLAN.md. Старый протокол сохраняется
на время перехода; наличие старых тестов не доказывает готовность новой схемы.

## Требуемый результат

- Сервер остаётся в Dockhand. CI публикует подписанные клиентские пакеты;
  сервер скачивает и проверяет выпуск один раз в постоянный Docker volume.
  Готовность версии объявляется только после атомарной публикации полного пакета.
- Служба на ПК проверяет назначение при старте и периодически после появления
  связи. Источник истины — сервер клуба, а не GitHub latest.
- Сервер хранит целевой и минимально допустимый выпуск. Идентификатор выпуска
  непрозрачен: строки/hash нельзя сравнивать как semver. Совместимость должна
  задаваться явно и проверяться сервером при выдаче нового доступа.
- Каждый ПК обновляется независимо. Выключенный ПК догоняет при включении;
  занятый продолжает сессию. Никакого ожидания всех ПК и принудительного
  завершения игры. Ошибка одного не закрывает остальные ПК.
- Перед установкой: свежая готовность GUI, нет активного ledger/сессии,
  неподтверждённых финансовых фактов; серверный запрет новых сессий только для
  этого ПК и повторная проверка под запретом. Проверка/запрет атомарны с новым
  входом, восстановлением grant и переносом.
- Скачивание в staging, проверка закреплённой подписи, размеров и SHA-256;
  замена EXE, проверка запущенного GUI и независимое серверное подтверждение.
  При сбое восстановление после перезапуска и откат. Ошибка оставляет закрытым
  только этот ПК до исправления. Конфигурация/identity/ledger/outbox сохраняются.
- При потере связи не снимать уже установленную блокировку. Начатая игра
  сохраняет прежний V2 offline-контракт. Отсутствие проверки совместимости
  не является разрешением нового доступа после обязательного обновления.
- Настройки оператора показывают весь парк, назначенную и запущенную версии,
  ожидание включения/конца сессии, установку, подтверждение и ошибку каждого ПК.
- Несовместимые изменения сервера требуют отдельного окна обслуживания.
  Самообновление watchdog в этот этап не входит: его первоначальная установка
  и обновление выполняются установщиком. Обновляется GUI HubShell.exe.

## Последовательность реализации

1. Контракты и атомарные независимые барьеры Sessions.
2. Постоянное назначение выпуска и отдельные задания ПК, без глобального
   ограничения одного незавершённого задания. Защита от двух заданий на одном
   ПК и от конфликта с оставшимся общим обслуживанием. Идемпотентность команд.
3. Автоматическое продвижение задания на сервере при опросе службы:
   readiness → локальный барьер → новый раунд → установка → подтверждение.
   Снятие барьера одного ПК не зависит от успеха остальных.
4. Проверка целевого/минимального выпуска во всех путях нового доступа,
   привязка GUI release metadata к аутентифицированному устройству.
5. Серверная доставка зеркала и переключение назначения после проверок
   backend; запуск по расписанию, credentials вне Git, восстановление после
   прерывания. Не менять чужие Docker volumes и секреты.
6. Служба/GUI: старт, офлайн, повтор после включения, идемпотентный повтор,
   восстановление, блокировка несовместимого клиента. Существующие подписи,
   installer, HTTP, DPAPI и IPC использовать повторно.
7. Статус в существующем UI, документация установки и сборка поставки.

## Проверки и границы

Локально доступны Linux, Docker/PostgreSQL, .NET test host. Проверять HTTP,
транзакционные гонки входа/переноса с барьером, независимость ПК, подписи,
ошибки скачивания/запуска и восстановление процессов на доступном host.
NAS и Windows недоступны пользователю примерно неделю: не пытаться
подключаться, не объявлять SCM/WTS/DPAPI/ACL и реальный Dockhand проверенными.
Подготовить короткий очный сценарий установки и обновления двух ПК.

остаётся открыт; explicit retry второго заканчивается успехом. Настройки и

### Серверный допуск и повторная установка — 2026-11-06

Реализована свежая GUI-версия, привязанная к installation_id в enrollment JWT
(миграция 0089). Новый public Sessions gate подключён в bootstrap к сеансам,
переносам и выдаче V2 snapshots. Изменение policy/наблюдения использует тот же
admission lock; оба порядка гонки с новым входом проверены. Активная игра и
обработка подписанных ранее финансовых фактов не прерываются. Xbox исключён.
Обнаружена и исправлена старая глобальная проверка неизвестной новой сессии:
при snapshot issue теперь передаётся workstation_id, барьер другого ПК
не мешает новому входу на свободный совместимый ПК.

GUI отправляет свой embedded release_id, блокирует новый вход до проверки/при
потере связи; IPC completion сохраняет блок несовместимости. Сообщение больше
не требует ждать весь парк. Возврат старого EXE после completed
создаёт repair-задание; сценарий прошёл с настоящим .NET агентом через TCP.

Проверки: 77 backend release/auth/admission tests до последней регрессии
unknown-session scope; отдельные 38 enrollment/V2 login/guest/transfer tests;
2 .NET/TCP/HTTP/PostgreSQL E2E с repair; 62 .NET access-gate/visibility/update tests.
Windows host собран на Linux: 0 warnings/errors. 0089 downgrade/re-upgrade прошёл.
Новая регрессия scope: 45 admission/V2 login/guest tests прошли.
Дополнительно: 13 PostgreSQL reconciliation tests прошли, 1 Kafka/Redis
worker test пропущен без broker settings; 11 HTTP/gRPC enrollment tests прошли.
Production V2 gRPC enrollment также выдаёт installation_id в device JWT.
Остаются CD-публикация назначения, конфигурация зеркала/ключа и расписание,
статус всех ПК в UI, поставка и короткая инструкция очной проверки.
