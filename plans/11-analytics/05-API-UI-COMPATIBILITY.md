# Этап 5 — сравнение периодов, API и интерфейс

Статус: `planned`  
Приоритет: `P1`  
Зависимости: этапы 1–4, `04-auth-security`, `frontend/PLAN.md`

## Цель

Подготовить безопасное расширение аналитики и интерфейса без изменения смысла
действующих HTTP/gRPC/CSV контрактов. Реализацию новых endpoints и DTO можно
начинать только после отдельного согласования версии.

## Границы совместимости

- текущие `AnalyticsService.GetOverview`, `GetClient` и `overview.csv` остаются
  неизменными;
- текущие поля не получают новый смысл;
- обязательные поля в protobuf и JSON не добавляются;
- для новых данных использовать additive-поля, новую версию или отдельный
  endpoint после contract review;
- UI не вычисляет новые финансовые показатели самостоятельно.

## Плановые задачи

1. [ ] Описать comparison period: предыдущая равная длина, МСК, граница
   незавершённого периода и статус `partial`.
2. [ ] Подготовить фильтры по периоду, зоне, ПК, тарифу, клиентской группе,
   способу оплаты, типу операции, товару и оператору.
3. [ ] Описать drill-down references для оператора без выдачи лишнего PII.
4. [ ] Спроектировать версионирование новых read DTO, не меняя текущий v1.
5. [ ] Подготовить UI-блоки «Финансы», «Загрузка», «Клиенты», «Места»,
   «Тарифы», «Товары» и «Депозиты».
6. [ ] Описать общий `MetricInfo`: маленькая иконка, описание, формула,
   источник, состояние `нет данных` и поведение при наведении/фокусе.
7. [ ] Подготовить browser smoke сценарии для подсказок, фильтров, сравнений,
   прав оператора и сохранения текущего CSV flow.

## Артефакты

- API compatibility matrix;
- proposal для `analytics.v2` или additive read contract;
- каталог UI-метрик и текстов подсказок;
- mapping filter → source fact;
- browser smoke matrix.

## Проверки

- существующие v1 consumers получают прежний response;
- оператор видит drill-down только при нужном permission;
- каждая метрика имеет формулу и источник в `MetricInfo`;
- hover и keyboard focus открывают подсказку в обычном браузере;
- отсутствие данных не превращается в фиктивный ноль;
- текущий CSV download продолжает работать без изменения формата.

## Готовность

Этап готов, когда версия будущих контрактов и UI-каталог согласованы, а
решение не требует изменения действующих контрактов для запуска текущего
приложения.

## Не входит

Фактическая реализация новых API, миграция protobuf, тяжёлые фоновые отчёты,
XLSX/PDF, realtime transport и изменение текущих экранов до contract review.
