# Avalonia Windows client product contract

## Режимы клиента

- До авторизации Avalonia-клиент показывает полноэкранный заблокированный access-gate с
  номером места, входом и регистрацией.
- При запуске access-gate должен быть виден уже в первом отрисованном кадре;
  промежуточный белый или пустой экран недопустим. До авторизации используется
  тёмная палитра клиента даже при светлой системной теме Windows.
- После входа пользователь получает обычный Windows-рабочий стол: приложение не
  заменяет Windows собственным shell.
- После входа Avalonia-клиент сворачивается в небольшой borderless-виджет без системных
  кнопок окна. Его можно скрыть в трей собственной кнопкой.
- После входа виджет располагается у правого края рабочего стола. Аватар не
  используется: виджет показывает ник, телефон, баланс, доступное время,
  оставшееся время активной сессии и явную кнопку выхода.
- Интерфейс Win-клиента использует согласованную тёмную палитру: графитовый
  фон и карточки, светлый текст и lime-зелёный акцент. Системная светлая тема
  Windows не должна переключать клиент в белую палитру.
- В виджете есть каталог опубликованных тарифов. Покупка требует явного
  подтверждения и списывает деньги только через backend; сохранённый пакет
  можно отдельно активировать.
- В каталоге Win-клиента показываются только опубликованные активные тарифы,
  совместимые с зоной текущего workstation и аудиторией текущего покупателя;
  общий тариф без зоны совместим со всеми зонами. Для зарегистрированного
  клиента допустимы `all` и `registered`, для гостевой продажи — `all` и
  `guest`. Backend остаётся источником решения.
- Оплата оператора выполняется в web-оболочке. Смешанная оплата в MVP — это
  наличные плюс перевод; банковские карты не поддерживаются.
- Временной тариф содержит отдельные серверные окна продажи и расходования.
  Вне окна продажи он не попадает в каталог и не покупается; купленный пакет
  вне окна расходования не теряет минуты. Avalonia отображает каталог и
  уведомления из server snapshot и не определяет доступность по локальным
  часам.
- В активной гостевой сессии виджет показывает название оплаченного тарифа,
  количество блоков и оставшееся время из server snapshot. Для поминутного
  режима показывает оставшееся время по балансу и прошедшие минуты/метры из
  server snapshot; заглушка вместо времени допустима только если backend
  действительно не прислал ни тариф, ни meter, ни остаток по балансу.
- Во время активного пакета поле времени, рассчитанного по балансу, скрывается;
  оно появляется только после перехода на поминутный источник. Завершённые
  `exhausted` и `burned` пакеты в пользовательском списке не показываются.
  Видимые состояния пакета — только `Активный` и `В очереди` с названием
  тарифа, понятным остатком и длительностью.
- Отображаемый таймер считается локально от последнего подтверждённого
  server snapshot и монотонно уменьшается в рамках одного источника времени.
  Heartbeat/polling корректирует drift, но не заменяет каждую секунду скачком;
  финансовым источником истины остаётся backend. Переход package → следующий
  package → per-minute принимается только из server result.
- У пакета нет отдельной пользовательской кнопки «Завершить»: завершение
  игровой сессии выполняется только общей кнопкой «Выйти».
- Перенос сессии — вторичный сценарий и находится в сворачиваемом блоке, а не
  занимает основной экран.
- История аккаунта открывается в отдельном fixed-size borderless-окне в той же
  тёмной палитре. Она не изменяет размер основного виджета, показывает
  server-backed строки с локальным форматом времени `dd.MM.yyyy HH:mm` и
  всегда имеет явную кнопку закрытия.
- Выбор темы пользователем в виджете не показывается: тему назначает клуб и
  передаёт через workstation heartbeat.
- Название станции в access-gate и виджете приходит из server-backed
  `workstation.name` того же authenticated heartbeat. Технические
  `workstation_id` и device ID не выводятся пользователю; до получения имени
  показывается нейтральное «Игровое место».
- Регистрация и вход используют пароль, не PIN. Телефон вводится в устойчивой
  маске `+7 (9__) ___-__-__` и отправляется backend в canonical-виде.
- Успешные вход и регистрация на назначенном ПК создают одну server-backed
  активную сессию этого клиента на текущем месте. До ответа `SessionSnapshot`
  пользовательский виджет не считается запущенным.
- Если приложение/ПК перезапустились или связь временно пропала во время
  active session, authenticated heartbeat обнаруживает её снова, а Win-клиент
  восстанавливает portal/session state без повторного пароля. Resume разрешён
  только для сессии этого workstation; явный выход сначала завершает сессию.
- Выход выполняется по состояниям: запрос stop, подтверждение backend,
  очистка доступа и открытие access-gate, затем allowlisted restart. До
  подтверждения backend клиент не показывает успешное завершение и не
  запускает перезапуск; ошибка каждого этапа остаётся видимой и допускает
  безопасный повтор. Произвольные shell-команды запрещены.
- В пользовательском access-gate доступны только вход и создание аккаунта;
  ручная проверка подключения и вход менеджера не показываются. Состояние
  соединения обновляется автоматически.
- До пользовательского входа access-gate работает в `Locked`, всегда остаётся
  `Topmost`, а `Alt+Tab` и `Win+R` подавляются в локальном обработчике и должны
  быть подтверждены Windows policy/native smoke. Запрет произвольного запуска
  приложений пока не является частью базового lock.
- Режим обслуживания не имеет публичной кнопки в пользовательском access-gate
  и не запускает клиентскую сессию. Его отдельный контролируемый route описан
  ниже и реализован в клиенте.
- Скрытый менеджерский route допускается по `Ctrl+Alt+P` только когда
  заблокированное окно клиента имеет фокус. Комбинация открывает форму пароля,
  но сама по себе не даёт доступ; пароль проверяется отдельным PBKDF2-verifier.
  Глобальные keyboard hooks и `BlockInput` не используются.
- `Ctrl+Alt+Del` не перехватывается: Task Manager может быть запущен для smoke,
  но access-gate должен оставаться поверх обычного окна; это не заменяет
  Windows security boundary.
- В профиле `app_gate` после успешной проверки менеджер может скрыть application
  shell в трей и увидеть обычный Windows Desktop. Это не отключает Explorer,
  Start Menu, Alt+Tab или другие политики Windows. В production `shell_launcher`
  клиент остаётся shell-процессом, поэтому полноценное обслуживание Desktop
  выполняется отдельной maintenance/admin учётной записью. Любое временное
  изменение Windows policy, если оно будет утверждено отдельно, выполняется
  только явным обратимым platform-policy действием с audit и native Windows
  verification.

## Авторизация и регистрация

- Вход: `ник + пароль` или `телефон + пароль`.
- После операторского сброса аккаунт допускает вход с пустым паролем. Сразу
  после входа Avalonia-клиент показывает обязательную форму нового пароля с повтором;
  доступ к балансу, тарифам и сессии открывается только после совпадения полей
  и подтверждения backend.
- Регистрация: ник, телефон, пароль. После неё можно завершить flow и пополнить
  депозит у оператора либо сразу войти и получить 5 бесплатных минут.
- При активной сессии на другом месте обычный второй вход не создаёт сессию;
  клиенту предлагается подтверждённый перенос. После подтверждения на старом
  ПК новый ПК принимает тот же аккаунт обычным входом без ID/кода; старый ПК
  сначала очищает portal/access-gate state и только затем выполняет restart.

## Тарифы и уведомления

- При новом входе показать совместимый сохранённый пакет и предложить его
  активировать. Несовместимый пакет другой зоны показать с понятной причиной,
  не расходуя его.
- Новый тариф, купленный в активной сессии при пустой очереди, стартует сразу.
  После завершения пакета следующий совместимый пакет запускается автоматически.
- Если покупка тарифа отклонена из-за недостаточного баланса, клиент показывает
  явное уведомление «Недостаточно средств на балансе» в виджете; ошибка не может
  завершаться без видимой обратной связи.
- При автоматическом старте показать краткое уведомление: активированный тариф
  и остаток пакетов. Оно закрывается само через 3 секунды и имеет собственную
  кнопку закрытия.
- При исчерпании всех пакетов и баланса завершить сессию и перезапустить ПК.
- Пороговые уведомления приходят из server-backed notification rules. Клиент
  получает `time_notifications` в session snapshot через gRPC, дедуплицирует
  событие по его идентификатору, воспроизводит стандартный звук или разрешённый
  wav/mp3 через Windows adapter и показывает tray balloon как Windows notification.
  Offline/reconnect не должны повторять уже подтверждённое событие; Linux host
  использует no-op platform presenter и видимый portable banner.
- При нулевом или отрицательном балансе Win-клиент показывает `0 минут` и не
  рассчитывает кредитное время. Решение о продолжении поминутной сессии и её
  остановке принимает backend по группе клиента и лимиту долга.

## Бронирования

- Перед входом получать server decision. Не пускать, если backend вернул запрет
  из-за брони.
- В авторизованном виджете показывать компактную плашку только для будущей
  подтверждённой брони текущего игрового места, принадлежащей вошедшему
  клиенту. Если такой брони нет, блок полностью скрывается.
- Не показывать фиктивные, демонстрационные, гостевые или чужие брони; Avalonia-клиент не
  подставляет значение по умолчанию и не строит бронь из локального состояния.
- За 30 минут до начала любой брони блокировать вход. Для именной брони допуск
  назначенного клиента определяет backend.

## Связь и офлайн

- gRPC heartbeat выполняется не реже чем раз в 10 секунд; portal snapshot после
  входа обновляется отдельным коротким циклом не реже чем раз в 5 секунд. Это
  ограничивает задержку внешнего пополнения баланса без перехода на новый
  realtime-транспорт.
- При потере сети текущая сессия не прерывается. Виджет и клиент продолжают
  работать по последнему серверному снимку.
- Локально сохранять постоянный журнал расхода времени и операций, чтобы после
  reconnect отправить idempotent batch на backend. Нельзя хранить эти факты
  только в RAM или Redis.
- Если на локальном снимке заканчиваются пакет и баланс, завершить сессию и
  заблокировать ПК. Если сеть отсутствует до входа, новую сессию не запускать.
- На карте оператора офлайн-ПК остаётся виден с последним клиентом, временем и
  статусом отсутствия связи.

## Enrollment и темы

- Avalonia-клиент запускается автоматически с Windows, сообщает MAC и ждёт назначение
  оператором созданному месту.
- Неизвестный MAC остаётся на заблокированном экране до явной привязки.
- Тема приходит от backend для группы места; фон и визуальный стиль access-gate
  настраиваются темой, а не требуют отдельной сборки.
