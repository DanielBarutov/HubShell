# План 45. Гостевой запуск Steam

## Цель

Добавить отдельный от HubShell контур для разрешённого клубом запуска Steam под
гостевыми аккаунтами. Он не создаёт сессии HubShell, не меняет тарифы, баланс или
продажи и не получает доступ к основной базе HubShell.

## Границы

- `steam-guest` — самостоятельный .NET-сервис с собственной PostgreSQL-базой и
  внутренним HTTP API без web-интерфейса.
- `HubShellSteam.exe` запускается гостем вручную с рабочего стола. Он берёт один
  свободный аккаунт, запускает Steam и не показывает пароль.
- После подтверждённой команды `session.stop` текущий `HubShell.exe` отправляет
  только локальный сигнал. Он не передаёт деньги, клиента, тариф или команду
  Steam.
- Агент не подключается к `WatchCommands`: второй потребитель мог бы подтвердить
  команду раньше основного Windows-клиента.
- Хранилища не общие: сервис не читает таблицы HubShell, а HubShell не читает
  таблицы гостевых аккаунтов.

## Правила первой версии

1. Аккаунт может быть выдан только одной станции одновременно.
2. Повторный запуск на той же станции возвращает прежнюю активную аренду, а не
   занимает второй аккаунт.
3. При локальном сигнале завершения агент сначала закрывает Steam, затем
   освобождает аккаунт. Если освобождение не удалось, запись остаётся занятой
   для ручной проверки.
4. Ошибка запуска Steam не освобождает аккаунт автоматически: это исключает
   одновременную выдачу, пока оператор не проверит ситуацию.
5. Логин и пароль шифруются в базе отдельным ключом сервиса; пароль не выводится
   в HTTP-ответах оператора, журналах или интерфейсе.
6. Доступ агента ограничивается отдельным ключом конкретной станции. Управление
   аккаунтами и станциями требует другого ключа администратора.
7. Агент читает `.env` рядом с `HubShellSteam.exe`. Для закрытой локальной сети
   разрешён HTTP только при явном `HUBSHELL_STEAM_ALLOW_HTTP=true`.
